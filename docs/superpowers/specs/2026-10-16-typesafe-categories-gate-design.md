# Гейт категоризации через TypeSafe (Jev)

Дата: 2026-10-16. Задача из `docs/TODO.md`: «Подключить возможность категоризации сообщений через typesafe-ai».

Детали первого сценария (чаты, chat_id, target, источники разметки, черновик инстанса, выкат) лежат вне git: `data/typesafe-categories-sensitive/README.md`.

## Зачем

Первый сценарий — поиск лидов в тематических Telegram-чатах (одна папка, ~23 сообщения в день). Лиды не ловятся словами: боты и реклама подрядчиков содержат те же ключевые слова, что и запросы лидов, а часть терминов неоднозначна в предметной области. Нужна семантическая классификация каждого сообщения.

TypeSafe (модель Jev) отвечает на вопрос типа **Choice** выбором одной опции из заданного набора и распределением вероятностей по всем опциям. Это дешевле OpenAI-промпта (платится только вход, $0.042 за 1M токенов) и даёт типизированный ответ без парсинга.

Другие сценарии — после релиза, сейчас не проектируются.

## Цели

1. Новый гейт `categories` на уровне инстанса: список категорий, сообщение пересылается, если отнесено к одной из «пересылаемых» категорий.
2. Категория попадает в шапку пересылки в виде хэштега `#lead_direct`.
3. Глобальная настройка `ignore_bots`: отсекать отправителей, чей username заканчивается на `bot` (любой регистр).
4. Скрипт прогона гейта по выгрузке `telegram-download-chat` за 15 дней со сверкой с эталонной разметкой. Прохождение прогона — критерий готовности к выкату.
5. Выкат первой версии инстанса лидов в локальный тестовый контейнер (делает агент сам, после прохождения прогона). Прод — только по отдельному явному ок пользователя.

## Не цели

- Мультиметочная классификация (несколько хэштегов на сообщение).
- Замена `prompts` — оба гейта остаются, можно комбинировать.
- Изменение логики реакций 👍/👎, debounce, `once_per_chat`.
- Отсечение постов самого канала (отдельная задача; сейчас решается через `ignore_user_ids`).

## Анти-цели

- Нельзя ломать существующие инстансы: без ключа `categories` поведение и вывод шапки байт-в-байт как сейчас.
- Гейт не должен падать вместе с сервисом при ошибке TypeSafe API (сеть, 429, 5xx): ошибка логируется, гейт считается несработавшим, обработка идёт дальше (к `prompts`).
- Чувствительные данные (тексты сообщений, имена, разметка, названия чатов/папок, заказчик сценария) не попадают в git: всё в `data/` (он в `.gitignore`).

## Решения, принятые с пользователем

- **Категоризация — альтернативный гейт**, а не только метка: нет пересылаемой категории — нет пересылки.
- **Порядок гейтов: `words` → `categories` → `prompts`** (categories дешевле промптов). Если сработал гейт раньше — следующие не вызываются.
- **Имена категорий в нижнем регистре**: `lead_direct`, `lead_weak`, `reco_letters`, `competitor`, `other`. Хэштег = `#` + имя категории.
- **`lead_weak` пересылается** вместе с `lead_direct` и `reco_letters`.
- **`ignore_bots`** — глобальная настройка, правило: username оканчивается на `bot`/`Bot` (сравнение по `.lower().endswith("bot")`).
- **Прогон по выгрузке за 15 дней** — обязательная проверка до выката.
- **Эталонную разметку пользователь не проверяет**; первую версию агент выкатывает сам.

## Конфиг

Новый ключ инстанса `categories` (парсинг и валидация в `src/config.py` `load_instances`, документация в `README.md` и `config-example.yml`, а также в `skills/telegram-resender/`):

```yaml
typesafe_api_key: ""          # глобально; fallback — env TYPESAFE_API_KEY
ignore_bots: false            # глобально, по умолчанию выключено

instances:
  - name: Leads
    entities: ["@some_chat"]
    words: []
    categories:
      model: jev-latest       # по умолчанию jev-latest
      threshold: 0.5          # мин. суммарная вероятность пересылаемых категорий
      instructions: >-
        Мы помогаем клиентам с <услуги>. К какой категории относится сообщение из чата?
      forward:
        lead_direct: "Автор сам просит то, что мы продаём, или ищет подрядчика под свой кейс"
        lead_weak: "Ранняя стадия: сомневается, подходит ли ему услуга, спрашивает цену"
        reco_letters: "Ищет рекомендателей"
      reject:
        competitor: "Реклама подрядчиков, партнёров чата, предложение своих услуг"
        other: "Процессные вопросы, новости, офтоп, благодарности"
```

- `forward` и `reject` — словари `имя → описание` (описание может быть `null`). Все опции обеих групп уходят в один Choice-вопрос: `reject`-категории нужны как явный контраст, иначе модель обязана выбрать что-то из `forward`.
- Валидация: `forward` непуст; имена уникальны между группами; имена — `[a-z0-9_]+` (валидный Telegram-хэштег); `threshold` в `(0, 1]`.
- Реальные `instructions` и описания категорий первого сценария — в `data/typesafe-categories-sensitive/README.md`; подбираются на прогоне.

## Поведение гейта

1. Если у сообщения нет текста — гейт не вызывается (как `prompts`).
2. Один запрос `system_one` к TypeSafe: `state` — объект с текстом сообщения (и, на усмотрение билдера, названием чата), вопрос `category` типа Choice с `instructions` и `criteria` = `forward ∪ reject`.
3. `p_forward` = сумма вероятностей всех `forward`-категорий. Если `p_forward >= threshold` — пересылка. Категория для хэштега — самая вероятная из `forward` (не обязательно топ-1 общего распределения).
4. Триггер в шапке: `{trigger}` = `category: lead_direct 0.82` (вероятность выбранной категории, 2 знака). Новый плейсхолдер `{category}` = `#lead_direct`; пустая строка, если сработал не гейт категорий.
5. Дефолтная шапка (без `message_template`): при срабатывании гейта категорий отдельной строкой идёт хэштег, затем строки как сейчас. Для `words`/`prompts` вывод не меняется. *(Решение дизайнера.)* Хэштег управляется собственным флагом `forward_message.show_category` (по умолчанию `true`) и не зависит от `show_trigger`. Порядок: `prefix`, хэштег, trigger, source, `suffix`.
6. Ошибка API → `logger.warning`, гейт = не сработал, идём к `prompts`.
7. *(Решение дизайнера.)* `target_webhook` в формате `json` получает поле `category` (имя без `#`, `null`, если сработал не гейт категорий). Формат `text` не меняется.
8. Статистика: учитывать срабатывания гейта категорий в `stats` по аналогии с `used_prompt` (и токены — по возможности).

## `ignore_bots`

Проверяется в обработчике новых сообщений `src/app.py` там же, где `ignore_user_ids`, **до** цикла по инстансам и **отдельно от `ignore_usernames`**. Причина: попадание в `ignore_usernames` трактуется как «ответил владелец» и при `cancel_on_owner_reply` сбрасывает debounce-батч — сообщение бота не должно сбрасывать батч с лидом.

## Прогон по выгрузке

Источник — выгрузка `telegram-download-chat` (`messages.json` по чатам; путь передаётся аргументом). Пути к выгрузке и к заметке с критериями разметки — в `data/typesafe-categories-sensitive/README.md`.

1. **Эталонная разметка** — файл в `data/evals/` (вне git): `{message_id, chat, label}` для каждого текстового сообщения, `label` ∈ пяти категорий. Готовой поштучной разметки нет — есть только сводка по категориям и перечень лидов по авторам. Разметку делает билдер (агент) по критериям из заметки, сверяя итоговые числа и авторов со сводкой.
2. **Скрипт** `src/run_categories_eval.py`: `--instance` (берёт `categories` из конфига) или `--categories <yaml>`, `--export <path>` (один или несколько `messages.json`), `--gold <path>`; применяет `ignore_bots`, прогоняет гейт с ограничением параллельности, печатает матрицу ошибок, recall/precision по «пересылать/не пересылать», список промахов, и пишет поштучный отчёт в `data/evals/`.
3. *(Решение дизайнера.)* Отложенной выборки нет: лидов слишком мало (~15 сильных). Чтобы подгонка не маскировала качество, отчёт сохраняет **базовые метрики первого прогона** (стартовые описания категорий, до любых правок) рядом с итоговыми. Дальнейшая калибровка идёт по 👍/👎 на проде.
4. *(Решение дизайнера.)* Код мержится независимо от результата прогона: гейт общий и выключен без `categories`. Прогон — условие **выката инстанса лидов**, не мержа. Подбор не более ~5 итераций; если критерий не достигнут — остановиться, показать отчёт и спросить.
5. **Критерий готовности (решение дизайнера, стартовое):** все `lead_direct` и `reco_letters` пересланы; `lead_weak` — recall ≥ 70%; `competitor` пропущено не больше 3; доля пересланного среди `other` ≤ 10%. Если не выходит — подбирать `instructions`/описания категорий/`threshold`, итог зафиксировать в отчёте и в `data/typesafe-categories-sensitive/README.md`.

## Выкат

После прохождения прогона агент сам добавляет инстанс лидов в конфиг тестового контейнера и перезапускает его (порядок — в `data/typesafe-categories-sensitive/README.md`), затем проверяет по логам, что инстанс поднялся и гейт вызывается.

## Зависимости и окружение

- `typesafe-sdk` (Python, есть async-клиент `AsyncTypeSafeClient`) в `requirements.txt` / `pyproject.toml`.
- Ключ: глобальный `typesafe_api_key` в конфиге, иначе env `TYPESAFE_API_KEY` (в окружении разработки задан; на проде — проверить).
- Учесть `proxy_url`, если SDK его поддерживает (иначе — отметить в README).

## Риски

- **Язык.** По документации Jev лучше всего работает с английским, остальные языки «handled but not equally well». Чаты русскоязычные — прогон обязателен; если качество недостаточное, допустимо писать `instructions`/описания на английском.
- **Версия модели.** `jev-latest` — алиас, ответы могут меняться с релизами. Порог, подобранный на прогоне, зафиксировать вместе с версией из ответа (`response.model`); в конфиге можно указать конкретную версию.
